# `install.sh check`

A read-only report on whether this machine can run Sumi Shell and what would get in its way.

```sh
./install.sh check            # human-readable
./install.sh check --json     # machine-readable
./install.sh check --tree DIR # check another sumi/ tree
./install.sh check --install --enable
./install.sh check --install --no-units
```

It **never** installs packages, starts, stops or enables services, edits configuration, migrates state or writes files.

`--install` includes the installer preflight for the selected profile. It checks the
runtime and lock, destination ownership, any confirmed missing QML imports, usable CLI
features and, for managed installation, access to the user manager. The diagnostic uses
the same `qs` executable the user installer would put in the units. The normal report
also describes startup conditions and optional services. It cannot prove that a live
compositor will create the Wayland surfaces or that PAM will authenticate.
It describes the machine as it is, including when that is incompatible. It does not repair anything.

## Levels and exit status

| Level | Meaning |
|---|---|
| error | Sumi Shell can't start, can't be reached, or a core function (starting, locking, unlocking) will fail |
| warning | a feature will be missing, something is likely to conflict, or something could not be verified |
| info | facts: versions, which copy runs, what is unavailable and why |

Exit status: **0** no errors (warnings don't block), **1** errors found, **2** the checker itself failed. The counts are in
the report. Untested versions of Quickshell or Hyprland are warnings, not errors: an error needs evidence that something
the shell uses is missing.

## What it looks at

- **Quickshell:** that `qs` exists and supports what the shell uses (`qs ipc call`, `--no-duplicate`); its version.
- **QML modules:** every module the shell imports (read from the tree), looked up as a `qmldir` in Qt's QML directory
  (`qtpaths6 --query QT_INSTALL_QML`) and in `QML_IMPORT_PATH`/`QML2_IMPORT_PATH`.
- **Tools:** Python ≥ 3.11 (checked first, by bash); GNU `timeout`, `find -printf`, `stat -c`, `env -C`, by running them.
- **Hyprland:** installed, its version, and inside a session `misc:allow_session_lock_restore`. With Hyprland 0.57 or
  later (the running one or the installed binary, whichever is newer), a warning if your configuration is still
  `~/.config/hypr/hyprland.conf` — no `hyprland.lua`, or only the default one Hyprland writes
  (`hl.config({ autogenerated = true })`): since 0.57 Hyprland reads only Lua. A `hyprland.conf` left beside your own
  `hyprland.lua` is not reported. The configuration path given with `-c` or `HYPRLAND_CONFIG` isn't looked at.
- **Copies of the shell:** `quickshell/sumi` in `$XDG_CONFIG_HOME` and each `$XDG_CONFIG_DIRS`; default configs
  (`quickshell/shell.qml`) that hide them; which copy `qs -c sumi` starts; which ones run (`qs list`); whether commands
  from this environment reach the running one.
- **systemd units:** that the programs they run exist, that they are current, that the rescue unit is there, that the user
  manager has this Hyprland's environment and that `graphical-session.target` is active.
- **No user manager:** a confirmed absence is reported from the session bus; `python-dbus` is required for the
  login1 inhibitor transport used with elogind. An unreachable bus remains unknown.
- **Notifications:** who holds `org.freedesktop.Notifications` (asked to the bus), the shell's own setting, activation
  files and whether the bus can activate a server.
- **Polkit:** the shell's agent setting and other agents found running or enabled.
- **Legacy state:** wallpaper and theme files from an older rice that were not migrated.
- **Everything Settings → System → Environment detects**, with the reason for what is unavailable.

## What it can't guarantee

Some things can only be proven by running the shell. When the check can't tell, it says so instead of reporting an absence.

- **QML modules:** it reads `qmldir` files; it does not load the plugins. A module that is listed but broken, or a
  Quickshell that loads its modules from a path only it knows (for example a wrapper that sets `QML2_IMPORT_PATH`), can
  only be confirmed by starting the shell: `qs -c sumi` in a terminal fails with "module … is not installed". If the
  check can't find even Quickshell's or Qt's base modules, it warns that it couldn't verify them.
- **Polkit agents:** polkit offers no way to list registered agents. Agents are recognised by process name, so an agent
  with an unusual name, or one built into another program (for example another desktop shell), may not be seen ("No polkit
  authentication agent was detected"), and a process with an agent-like name may not be one ("seems to be running").
- **Notifications:** the bus says who holds the name and what can be activated; which program an activation file starts
  is read from the files in the usual service directories. A server started by other means may not be named.
- **Reachability:** whether commands reach the running shell is judged from the environment of whoever runs the check. A
  terminal with different `XDG_CONFIG_HOME`/`XDG_CONFIG_DIRS` than the shell's service sees something different.
- **Versions:** "tested" means the versions this release was tested with; other versions may work.
- **Outside Hyprland** (for example from a TTY) the session checks are skipped and the report says so.
